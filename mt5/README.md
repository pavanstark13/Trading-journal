# MT5 Integration

```
mt5/
├── Include/TradeBridge/   → copy to  <terminal>/MQL5/Include/TradeBridge/
│   ├── Crypto.mqh         SHA-256, HMAC-SHA256, UUIDv5
│   ├── EventId.mqh        deterministic event identity (mirrors the server)
│   ├── Json.mqh           minimal JSON writing / flat reading
│   └── Client.mqh         signed HTTPS transport + disk spool + backoff
├── Experts/               → copy to  <terminal>/MQL5/Experts/
│   ├── MasterTradeBridge.mq5
│   └── MemberTradeCopier.mq5
├── tests/
│   ├── event_id_vectors.json   generated by the backend test suite
│   └── EventIdParity.mq5       → copy to <terminal>/MQL5/Scripts/, run once
└── mocks/fake_ea.py       Python EAs speaking the same signed contract (CI)
```

The folder layout mirrors MetaTrader's own, so installation is a straight copy.

## Install — Master

1. Copy `Include/TradeBridge/` → `MQL5/Include/TradeBridge/`
   and `Experts/MasterTradeBridge.mq5` → `MQL5/Experts/`.
   (Find the folder via **File → Open Data Folder** in MetaTrader.)
2. In MetaEditor, open `MasterTradeBridge.mq5` and press **F7** to compile.
   Expect `0 errors, 0 warnings`.
3. **Tools → Options → Expert Advisors**
   - tick *Allow WebRequest for listed URL*
   - add `https://api.your-domain.com`
   This step is skipped more often than any other, and its symptom is error 4060 in
   the Experts log. The EA prints an explicit fix-it message when it sees that.
4. Tick *Allow Algo Trading* in the toolbar.
5. In the dashboard: **EA Installations → generate install code** for the master.
6. Drag the EA onto **exactly one chart** (any symbol — it listens account-wide) and
   paste the code into `InpInstallCode`. Set `InpApiBaseUrl` and `InpNamespace`.
   `InpNamespace` **must** match the server's `EVENT_ID_NAMESPACE`, or every event id
   will differ and idempotency will silently break.
7. The dashboard shows the installation green within 30 seconds.

Attaching to a second chart is refused: the EA takes a terminal-global lock, because
two instances would double every event.

## Install — Member

Same steps, with `MemberTradeCopier.mq5`. *Allow Algo Trading* is mandatory here — this
EA actually places orders. An administrator must approve the installation in the
dashboard before it receives any instruction.

## Verifying event-id parity

After **any** change to `EventId.mqh` or `Crypto.mqh`:

1. Copy `tests/EventIdParity.mq5` → `MQL5/Scripts/`, compile, and run it on any chart.
2. Every line must print `PASS`. A `FAIL` means the MQL5 and Python implementations
   have drifted — duplicate trades would be published and copied, with nothing to warn
   you. Do not deploy until it is green.

Expected values live in `tests/event_id_vectors.json`, regenerated by the backend test
suite. `backend/tests/unit/test_event_id.py` pins the Python side.

## Testing without a broker

- **Demo accounts** for both roles. MT5's transaction semantics are identical to live.
- **Strategy Tester** can drive `OnTradeTransaction` deterministically, but
  `WebRequest` is disabled there — test delivery separately on a demo chart.
- **`mocks/fake_ea.py`** speaks the identical signed contract, so CI runs the whole
  pipeline with no Windows and no MetaTrader:
  ```bash
  python -m mt5.mocks.fake_ea master --install-code ABCD-EFGH-JKLM-NPQR
  python -m mt5.mocks.fake_ea member --install-code WXYZ-1234-5678-9ABC
  ```
- **PAPER mode** covers the last mile: real master events, real planning and risk
  checks, simulated fills.

## Design rules these EAs follow

| Rule | Why |
|---|---|
| `OnTradeTransaction` never calls `WebRequest` | It is synchronous; blocking there stalls a terminal managing live money and MT5 drops later callbacks |
| Events queue in memory, flush on `OnTimer` | Batching, backoff and spooling all become possible |
| Unsent events spool to disk | A terminal restart or a network outage loses nothing |
| Event ids are deterministic | Replaying the spool cannot create duplicates |
| The member EA never decides a volume | Sizing and risk are server-side, testable and auditable |
| The member EA halts if the backend is unreachable | An emergency stop it cannot hear about must fail closed, not open |
| Orders carry a `client_tag` comment | Last-line defence against a double fill after a mid-order restart |
